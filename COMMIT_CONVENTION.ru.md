# Правила оформления коммитов

Формат сообщения для коммита:
`<тип>(<область>): <описание> -- <файл_или_папка>`

### Типы (Type)
- **feat**: Новый функционал или возможности.
- **fix**: Исправление багов или утечек ресурсов.
- **refact**: Рефакторинг и улучшение структуры кода.
- **chore**: Рутинное обслуживание, техдолг, конфиги.
- **docs**: Обновление документации или комментариев.
- **style**: Форматирование и правки стиля кода.
- **perf**: Оптимизация производительности или использования памяти.
- **test**: Добавление или правка тестов.
- **build**: Сборка проекта и внешние зависимости.
- **ci**: Скрипты интеграции и деплоя (CI/CD).
- **revert**: Откат изменений к прошлой версии.
- **sec**: Работа с безопасностью и уязвимостями.
- **init**: Первый коммит или инициализация.

### Правила форматирования
- **Область** (опционально): В скобках укажите модуль (напр. `network`, `api`).
- **Описание**: Кратко опишите изменения в повелительном наклонении.
- **Файл/Папка**: После разделителя ` -- ` укажите 1-2 главных файла или папку.

### Примеры
- `feat: add command line arguments support -- main.cpp`
- `fix(io): resolve null pointer dereference -- logger.h`
- `build: link external threading library -- CMakeLists.txt`
- `refact(parser): simplify state machine logic -- parser.cpp, parser.h`
- `style: apply clang-format -- /src/core/`
